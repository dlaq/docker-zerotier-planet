# 节点状态、时间与事件推送（v1.1.8）

本次复用 ZTNet 和已配置的 message-pusher 网关。管理页新增“最近上线”“最后通信”，推送设置位于 **系统管理 → 邮件 → 事件推送与消息模板**。

## 状态含义

| 页面字段 | 数据依据 | 边界 |
| --- | --- | --- |
| 直联（内网/公网） | Controller 的有效、活跃、首选物理路径；支持 IPv4 和 IPv6 | 表示 Controller → 节点，不代表任意两台客户端之间的路径 |
| 中转 | Controller 已收到该网络成员的配置请求，当前没有有效首选直联路径 | 不能据此推断客户端自身是否使用 TCP fallback |
| 离线 | 最近配置请求已超过 Controller 的在线窗口（当前 120 秒） | 判断存在检测延迟；不是设备关机时间 |
| 未知 | 采集失败、旧 Controller 缺少观测接口，或启动/新增后仍未形成可靠观测 | 不将采集失败当作所有节点离线 |
| 等待授权 | 成员未获网络授权 | 与传输连接状态分开显示 |
| 等待 IP 分配 | 已授权、允许自动分配、网络启用自动分配，但尚无托管地址 | 不等于客户端的 `REQUESTING_CONFIGURATION`，不伪造客户端状态 |
| 手动配置 IP / 未启用自动分配 | 成员或网络的地址分配设置 | RFC4193/6PLANE 自动生成的 IPv6 也视为已配置地址 |
| 最近上线 | 当前观测到的最近在线周期开始时间 | 升级前历史不回填；Controller 重启且没有离线证据时保留原记录 |
| 最后通信 | Controller 实际收到网络配置请求的时间 | 不再使用刷新页面的时间；不代表所有业务流量的最后一个数据包 |

页面时间按浏览器时区显示；消息使用带 UTC 标识的 ISO 时间。升级前的旧 `lastSeen` 属于近似刷新记录，在获得新观测前不当作可靠通信时间显示。

新增内部接口：`GET /controller/network/<nwid>/member-status`。沿用 Controller 的 `X-ZT1-Auth` 校验和管理网段限制；不增加公网监听。后台每轮完成后等待 15 秒再扫描所有已管理网络，不依赖用户浏览页面。页面本身继续使用原有 Socket.IO 同步。

## 已接入的事件

- `node.added`：新发现、手动新增或恢复成员；手动新增同时创建 Controller 成员。
- `node.online` / `node.offline`：首次上线或观测到上下线变化；既有成员升级时只建立基线。
- `node.connection.changed`：在线节点直联/中转路径状态持续变化至少 30 秒；未知状态会中断确认。
- `node.authorized` / `node.deauthorized`：授权状态改变。
- `node.config.changed`：名称、地址、自动分配或网桥等配置改变。
- `node.removed`：成员从 Controller/管理数据库移除。
- `user.login.succeeded`：完成本项目账号校验及适用的 MFA 校验后建立会话。
- `user.password.changed`：用户成功修改密码。
- `user.password.reset_completed`：成功消费一次性重置凭据并修改密码；正文明确全部会话已经撤销。

节点正文包括网络名/ID、节点名/ID、托管 IP、物理地址、版本、授权、前后状态、时间、持续时长、操作人/观测来源和建议。账号正文包括账号、操作、来源 IP、设备、结果和建议。没有采集到的信息明确标为未知，不填写猜测值。

此次实现的范围为上列事件。客户端 TCP fallback、客户端真实 IP 应用失败、登录失败阈值、MFA 配置改变和 Controller 身份变化仍属于后续独立事件，不从有限的 Controller 数据推断。

## 模板与发送语义

每类事件可以独立启停、编辑标题/正文、查看可用变量、预览和恢复默认内容。模板只支持允许列表内的 `{{变量}}`，不执行代码，也不能访问密码、令牌、Cookie 或任意对象属性。消息发送前保存模板版本与已渲染正文；后续修改模板不会改变队列中的历史消息。

全局 Message Pusher 是**管理员运维目的地**。用户登录信息与网络信息会发送到该目的地，应限制其可见范围。个人邀请、邮箱验证和密码重置链接通过 SMTP 发送给对应用户，不能由全局推送代替。

发送通过 PostgreSQL 持久化队列执行；节点状态及相关事件在同一数据库事务中提交。登录会话同时作为恢复来源，启动后可补录尚未入队的新会话，既有会话迁移时只建基线。

网关请求使用 `async: false`、纯文本 `description` 和 `render_mode: raw`。只有 HTTP 成功且 JSON `success === true` 才标记“网关已确认”，不等同于用户已阅读。HTTP 200 内的 `success: false`、无效 JSON、超限响应及请求中断均不能算成功。

上游网关没有严格幂等保证。发送中断或无法确认结果时，记录为“结果未知”，不盲目自动重发；管理员检查目标渠道并接受可能重复后可手动重试。更换目的地会取消旧目的地的排队消息；超过 24 小时的未发送消息取消，已结束记录保留 30 天。

## 升级与回退

必须一起升级 ZeroTier 与 ZTNet；旧 Controller 没有新观测接口时，不会伪造网络级在线时间。升级前保存现有 Compose、环境文件、Controller/Planet 身份与数据库逻辑备份。新增字段和两张通知表均为兼容性扩展，不重新生成 Controller 身份，不改网络 ID、Planet 文件或客户端配置。

回退应用镜像可以保留新增表/字段；如要回退数据库，使用升级前的逻辑备份。测试 VPS 的身份、端口、网络和成员数必须在升级前后独立核对。

验证入口：`scripts/security-gate.sh`、`scripts/integration-smoke.py`，以及新增的节点观测、模板、网关响应及界面回归测试。容器集成测试使用独立网络、随机项目和测试推送接收器，不发送给真实外部收件人。
