# 2026-09-08 缺陷修复与安全复查记录

本记录对应当前工作树的安全修复；修复后的 `v1.1.2` 已在 AMD64 和 ARM64 原生 runner
上重新构建、扫描、生成 SBOM，并由门禁合成 Docker Hub 多架构标签。生产主机上的容器、
数据库和 `./data/` 未在本次复查中修改。

## 已修复的缺陷

### 认证、会话与权限

- Better Auth Prisma adapter 开启事务；直接注册、改密、重置密码接口关闭，注册只能走
  ZTNet 的邀请/注册流程。Better Auth 的服务器字段设置为不可由请求写入，密码哈希、临时
  密码、2FA 密钥不会返回浏览器。
- 注册使用 PostgreSQL advisory lock，邀请次数消费、组织邀请消费、用户、UserOptions、
  Better Auth credential Account 和首次关闭开放注册在同一事务中完成；并发首个注册只会
  产生一个管理员。OAuth 首个管理员提升也在提交后事务锁内完成。
- 统一邮箱规范化和可配置密码策略（默认 14--128 位、至少两类字符、bcrypt cost 12）。
  登录失败锁定在冷却结束时清零，防止一次旧失败计数立即重新锁死账户。
- 密码修改、密码重置同步 `User.hash` 与 Better Auth `Account.password`。重置令牌保存
  SHA-256 摘要、15 分钟有效并在一次成功事务中删除，同时清理现有会话。
- 每次受保护 API 请求重新检查用户启用状态、账户/用户组过期时间和当前角色；管理员停用
  用户后旧 Cookie 立即失效。`auth.me` 只返回凭据存在标志，不返回 Controller/Central
  密钥。`setLocalZt` 限定管理员，避免携带全局 `ZT_SECRET` 的任意 URL SSRF。
- Better Auth 起源、Fetch Metadata/CSRF、可信反向代理 IP 和登录/注册/重置限流均开启；
  `X-Forwarded-For` 只取可信链末端，代理网段由 `ZTPLANET_TRUSTED_PROXIES` 配置。
  OAuth 按真实 `/callback/:id` 路径识别，危险的邮箱自动绑定默认关闭，必须显式设置
  `OAUTH_ALLOW_DANGEROUS_EMAIL_LINKING=true`。
- 管理员创建用户、组织关系、网络删除和空对象/不存在对象路径增加事务、角色、空值和
  ownership 检查；全局管理员删除普通用户时使用显式 `adminOverride`，并在删除前保存网络
  名称，保证删除和审计通知不会失败或丢名称。

### Planet/mkworld 与 2FA

- mkworld 上传不再使用 `entry.on("end", async ...)` 与 `close` 的竞态。压缩包按顺序读取，
  只接受四个固定文件名，限制单文件 1 MiB、总解压 5 MiB、条目数 64，并拒绝重复条目。
  配置先在私有临时目录解析和运行 `ztmkworld`，确认输出为非空且不超过 16 MiB 后才原子
  写入持久目录；上传临时文件始终清理。空 rootNodes、空 endpoint、坏 JSON、坏端口现在
  返回 400，不再异步抛出 500 或部分写入数据库；所有 root 节点的端口都会参与校验，避免只读取第一个 root 导致 local.conf 漂移。
- Planet 端口严格限制为 1--65535 的一或两个唯一值；`local.conf` 使用随机临时文件和
  原子 rename，生成失败不会先改变运行端口。管理端生成 Planet 也在生成成功后才更新
  `local.conf`。
- 2FA setup/enable/disable 对空或非对象请求体返回明确 400；MFA 恢复码校验现在按顺序
  比较并在事务中一次性消费，修复原异步 `Array.filter` 始终保留所有恢复码的问题，并
  防止并发请求重复使用同一个恢复码。JWT payload 结构和 OAuth/MFA 用户无本地密码路径
  均有显式检查。

### 邮件、API 与中继

- 邮件模板键改为枚举白名单，缺失或损坏的数据库 JSON 回退内置模板，模板正文限制
  256 KiB；邀请过期时间限制为 1--525600 分钟、使用次数为 1--100000，避免无效日期和
  无限资源输入。
- REST 请求体允许缺省，组织集合接口不会把 `undefined` 当组织 ID 查询；用户/网络/令牌
  越界路径统一返回 401/403/404，而不是未捕获 500。
- Rust TCP fallback relay 增加严格拆包/粘包与绝对握手截止时间、全局连接 CAS、每 IP
  上限、IPv4 公网单播目标白名单、UDP 回包来源校验、请求产生的响应额度、全局/连接限速、
  metrics 写超时和最小容器权限。默认仍关闭，443 只是建议值；协议本身不是 TLS，也没有
  客户端认证，界面会显示此风险。

## 有意保留、需要部署者确认的风险

1. 用户可以在 GUI 选择公网/通配管理监听、HTTP、直接暴露 Controller 或 relay 任意来源；
   这些不是安全默认值，会显示风险并写入审计记录，不能被报告为“安全配置”。
2. ZeroTier TCP fallback 的外层是伪 TLS 帧而非标准 TLS，协议没有客户端认证。启用时应
   使用云防火墙和 `RELAY_ALLOWED_CIDRS`，并设置连接、包速率和带宽上限。
3. WebSocket 在握手时检查活动会话；已有连接上的每条消息不会重新查询数据库。撤销后应
   通过会话失效/重连策略关闭旧连接，不能把 WebSocket 当作长期授权缓存。
4. 本地 Controller token 是高权限凭据，仅管理员可修改；`ZT_ADDR`/`ZT_SECRET` 环境变量
   仍然优先于数据库配置。部署者必须限制 ZTNet 管理入口来源。
5. UDP 直连、根节点 `RELAY`、TCP fallback `TUNNELED` 和关闭 fallback 的失败矩阵需要在
   目标 VPS、运营商网络和两台测试客户端上实际验证；本地隔离烟测不能证明公网 NAT 行为。
6. `v1.1.2` 的发布摘要和门禁证据见 [安全审计报告](SECURITY-AUDIT.md)；面向部署者的
   Compose 已固定到该版本的新 digest。后续重建或更换基础镜像仍须重新执行完整门禁。
